# Umami Deployment & Configuration

## Overview

Umami is a privacy-focused analytics platform self-hosted on Arthur. It tracks analytics for joeclark.photo and the CRM frontend.

- **Repository:** This repo (`arthur-infrastructure`)
- **Installation:** `/opt/umami/`
- **Database:** PostgreSQL (local, separate from CRM)
- **Port:** 3002 (reverse-proxied via Apache to `umami.joeclark.photo`)
- **Service:** systemd unit `umami.service`

## Installation (Fresh Setup)

**Prerequisites:**
- PostgreSQL installed and running
- Node.js 18+ available
- Apache2 with mod_proxy enabled

**Steps:**

1. **Pull the repo:**
   ```bash
   ssh hetzner "cd /opt && git clone https://github.com/joeclarkx/arthur-infrastructure.git"
   ```

2. **Run the setup script:**
   ```bash
   ssh hetzner "bash /opt/arthur-infrastructure/scripts/setup.sh"
   ```

   This script:
   - Installs PostgreSQL if missing, creates the `umami` DB and role
   - Clones Umami source into `/opt/umami` and checks out the latest v2.x tag
   - Writes `/opt/umami/.env` (DB password + `APP_SECRET` generated automatically)
   - Installs Node dependencies, runs Prisma migrations, builds the app

3. **Install the service and reverse proxy:**
   ```bash
   ssh hetzner "cp /opt/arthur-infrastructure/scripts/umami.service /etc/systemd/system/umami.service"
   ssh hetzner "systemctl daemon-reload && systemctl enable --now umami"
   ssh hetzner "cp /opt/arthur-infrastructure/scripts/apache-vhost-umami.conf /etc/apache2/sites-available/umami.conf"
   ssh hetzner "a2ensite umami && a2enmod proxy proxy_http && systemctl reload apache2"
   ```

4. **Verify installation:**
   ```bash
   ssh hetzner "systemctl status umami"
   ssh hetzner "curl http://localhost:3002"
   ```

5. **Get a cert once DNS for `umami.joeclark.photo` points at Arthur:**
   ```bash
   ssh hetzner "certbot --apache -d umami.joeclark.photo"
   ```

6. **Access the web UI:**
   - Navigate to `https://umami.joeclark.photo` in browser
   - Default credentials: `admin` / `umami` (change immediately)

## Configuration

### Environment Variables

Deployed as `/opt/umami/.env` on Arthur, generated by `scripts/setup.sh`:

```bash
DATABASE_URL=postgresql://umami:PASSWORD@localhost:5432/umami
APP_SECRET=random-32-byte-hex-string
PORT=3002
```

`APP_SECRET` is generated with `openssl rand -hex 32` by the setup script — no manual step needed.

### Apache Reverse Proxy

Located in `config/apache-vhost-umami.conf`. Deployed to `/etc/apache2/sites-enabled/umami.conf`.

Handles:
- HTTPS termination (Let's Encrypt cert)
- Reverse proxy to `http://localhost:3002`
- Static file caching
- Compression

## Updates & Maintenance

### Upgrade Umami

Check for new releases: https://github.com/umami-software/umami/releases

To upgrade:
```bash
ssh hetzner "cd /opt/umami && git fetch && git checkout v2.X.X"
ssh hetzner "cd /opt/umami && npm install && npm run build"
ssh hetzner "systemctl restart umami"
```

Then verify: `https://umami.joeclark.photo`

### Database Maintenance

PostgreSQL maintenance (weekly):
```bash
ssh hetzner "sudo -u postgres vacuumdb umami"
ssh hetzner "sudo -u postgres reindexdb umami"
```

## Troubleshooting

### Service Won't Start

1. Check logs:
   ```bash
   ssh hetzner "journalctl -u umami -n 30"
   ```

2. Check database connection:
   ```bash
   ssh hetzner "psql 'postgresql://umami@localhost/umami' -c 'SELECT 1'"
   ```

3. Check Node.js version:
   ```bash
   ssh hetzner "node --version"
   ```

### High Memory Usage

Monitor: `ssh hetzner "free -h && ps aux | grep umami"`

Solutions:
- Archive old event data (see maintenance.md)
- Increase server RAM
- Check for database query slowness

### Apache Not Proxying

1. Check Apache status: `ssh hetzner "systemctl status apache2"`
2. Check mod_proxy is enabled: `ssh hetzner "apache2ctl -M | grep proxy"`
3. Check Apache config: `ssh hetzner "apache2ctl -t"`
4. Reload Apache: `ssh hetzner "systemctl reload apache2"`

## Excluding Your Own Visits

Umami has no "ignore admin" option — being logged into the dashboard does not
exclude your own pageviews. Two mechanisms exist, and we use both:

**1. `IGNORE_IP` (server-side, in `/opt/umami/.env`)**

Comma-separated IPs or CIDRs; matching pageviews are dropped on ingest
(`hasBlockedIp` in `src/lib/detect.ts`). Managed by `scripts/setup.sh`.
Requires a restart: `systemctl restart umami`.

Home IP is dynamic, so re-check it whenever your own traffic reappears:

```bash
curl -s https://api.ipify.org          # current IP
ssh hetzner "grep IGNORE_IP /opt/umami/.env"
```

**2. localStorage opt-out (per browser, survives IP changes)**

In the browser console on joeclark.photo:

```js
localStorage.setItem('umami.disabled', 1)
```

The tracker checks this flag and sends nothing. Repeat per browser/device, and
note it is cleared if you wipe site data.

Neither removes already-recorded visits — delete those in the Umami UI under the
website's settings if the history matters.

## Data Privacy

- Umami does not track personally identifiable information (PII)
- IP addresses are hashed
- No cookies used (GDPR/CCPA compliant)
- Data retention: Keep indefinitely (can be archived manually)

See https://umami.is/docs/privacy for full details.
